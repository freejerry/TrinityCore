# spell_script_names: WotLK-correct data (type-diff table)

**Verdict:** TDB335 (confidence: medium). Columns match 343/335 up to cosmetic type differences.

- **Rows:** world_d=2784, world_335=2692 | pattern: partial_overlap
- **Structure:** Schema is functionally identical in both DBs: (spell_id INT NOT NULL, ScriptName VARCHAR/CHAR(64) NOT NULL, UNIQUE KEY(spell_id,ScriptName)). Only cosmetic difference: world_d uses varchar(64), world_335 uses char(64) — no semantic effect. Column semantics: spell_id maps a spell (negative = apply to all ranks, per ObjectMgr::LoadSpellScripts) to a C++ SpellScriptLoader whose registered name equals ScriptName; a row only does anything if the compiled core registers a loader of that exact name (else ValidateSpellScripts disables it) AND the spell_id resolves in the client. So this table is tightly coupled to the core's registered scripts, not free content.

## Difference

1841 rows common. 943 rows exist only in world_d (343); 851 rows exist only in world_335. No pure value-shift rows (both columns are the key, so a diff is an add/drop, not an in-place edit). The 943 343-only rows are overwhelmingly post-WotLK scripts and post-WotLK spell-id bindings: Cataclysm (Firelands baleroc/alysrazor/argaloth, Silverpine/husam/anhuur quests, sha_earthquake, warl_soul_swap), MoP (monk_*, mage_alter_time, pri_atonement rework), WoD, Legion (dh_*, mardum, sephuzs_secret, artifact items, rog_roll_the_bones), BfA (azerite_*, gen_war_mode_enlisted, heart_of_azeroth), Shadowlands (torghast_*, soulbind_*), Dragonflight (evo_*/dracthyr, ruby_life_pools, anduin_wrynn Sepulcher raid). It also includes WotLK-era generic scripts (e.g. spell_gen_arena_drink, spell_gen_clone) bound to NEW post-WotLK spell ids — the WotLK spell-id bindings for those same scripts are already in the common set. The 851 335-only rows are authentic WotLK content: class talents/procs (dk_*, dru_*, pal_*, sha_*, warl_*, warr_*, mage_*, pri_*, hun_*, rog_* — many negative/all-ranks talent ids), and encounter scripts for ICC (marrowgar, sindragosa, blood_queen, professor_putricide, deathbringer_saurfang, rotface, festergut, the_lich_king), ToC (jormungars, icehowl), Ulduar (mimiron, thorim, algalon), AQ/Naxx/Kara/SSC/TK/Sunwell/ZA, plus WotLK dungeon/quest helper scripts and WotLK generic scripts (spell_gen_dungeon_credit, spell_gen_cancel_aura, etc.).

## Correct WotLK dataset

The WotLK-correct set is exactly world_335's content (2692 rows): drop all 943 343-only rows (post-WotLK scripts and post-WotLK spell-id bindings that 3.3.5a never had) and add all 851 335-only rows (WotLK class talents/procs and WotLK raid/dungeon/quest encounter scripts). Result == world_335 verbatim. Rationale: spell_script_names is core-coupled reference data; 3.3.5a TrinityCore (world_335) is the authoritative WotLK registration set, and the wotlk_classic core has re-added the WotLK encounter scripts (verified: spell_the_lich_king_defile, spell_putricide_slime_puddle, spell_marrowgar_bone_storm, spell_icehowl_massive_crash, spell_dk_death_coil all registered in this repo). The 343 additions are demonstrably post-WotLK content whose spells do not exist in 3.3.5a.

## Verification notes

The proposed set == world_335 (WotLK-authentic). Two classes of rows need the orchestrator's DBErrors.log / client-validation pass to confirm, but should NOT be silently dropped as they are 3.3.5a-correct: (1) ~561 distinct 335-only ScriptNames are not currently registered in the wotlk_classic core (all WotLK class talent/proc scripts like spell_dk_scourge_strike, spell_hun_explosive_shot, spell_rog_honor_among_thieves, spell_warr_overpower, spell_pal_seals, and helpers spell_gen_dungeon_credit / spell_gen_cancel_aura / spell_sha_healing_stream_totem). At load these produce 'unused script name' / disabled-script conditions (not fatal) — they will only fire once the core ports the matching SpellScriptLoaders (this is a known core-side gap, not a data error). (2) Some 335-only rows use spell_ids/ranks that must be confirmed present in the 3.4.3 client's Spell/SpellName store (I did not exhaustively verify each of the 2692 spell_ids against the client per the standing instruction that SpellName.db2 is not a reliable oracle here). Rows whose spell_id the running core cannot resolve will be logged to DBErrors.log ('Scriptname ... spell (Id: N) does not exist') and skipped — the orchestrator should trim exactly those. Confidence is medium (not high) precisely because of these two unverified-in-3.4.3 dimensions; the WotLK-authenticity of the world_335 set itself is high-certainty.
